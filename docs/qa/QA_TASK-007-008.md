## 6. 결론

- **공통 BLOCKED 사유:** 두 TASK의 기능 구현과 자체 검증은 확인했으나, 동일 구현자가 작성한 보고서여서 독립 QA 기준을 충족하지 않는다. 사람 승인·PR/병합도 미수행이다.
- **TASK-007 추가 보류:** OQ-19의 표시 포맷·번역 정책은 OPEN. 최종 정책 확정 또는 현재 표시 방식 수용 여부를 사람이 결정해야 한다.
- **TASK-008 남은 개선점:** D-008-01의 해제 후 키보드 포커스 관리. 현재 기본 키보드 조작은 가능하지만 개선은 아직 구현하지 않았다.
- **남은 위험·미검증:** 배포 origin CORS, 원격 데이터의 이후 변경, 검증 해상도 외 환경, Chromium 외 브라우저, 독립 QA, 담당자 승인·PR·CI·병합. 청크 크기 경고가 있으나 합의된 성능 기준 위반으로 단정하지 않는다. TASK-007 당시 작업 기록과 지속 보관된 원시 실행 로그는 현재 파일로 재확인할 수 없다.
- **수정 요청:** D-007-01의 오래된 주석 정리와 D-008-01 포커스 관리 개선. 독립 검증자가 각 TASK의 명령과 인수 기준을 재현한 뒤 QA 판정을 갱신한다. 이 문서 편집에서는 제품 코드를 수정하지 않았다.
- **사람 승인자:** 실제 승인 기록 미확인. ADR-014의 성윤우 작업 교차 확인 대상은 김형균. 기능 병합은 성윤우, 공통 변경 병합은 김형균 담당이다.
- **공통·상세·도감 변경:** TASK-007 공통 대응표 변경은 별도 공통 PR 선행 반영, 상세 호출부는 상세 담당자 확인 필요. TASK-008 도감 공개 export는 도감 담당자의 결과 확인 필요. 로컬 변경 요청 기록만으로 담당자 승인·병합을 완료 처리하지 않는다.
- **문서 갱신 별도 TASK:** QA PASS 이후 별도 승인 문서 작업으로 TASK 상태·OQ-19 결정 기록을 갱신한다. 현재 `docs/TASKS.md`의 TASK-007·008은 BACKLOG이며, 이 보고서에서는 상태·명세를 변경하지 않았다.
- **보고서 작성 변경 범위:** `docs/qa/QA_TASK-007.md`를 `docs/qa/QA_TASK-007-008.md`로 이름 변경하고 TASK-008 검토 내용을 추가. 제품 코드·테스트·정책 문서 수정, 커밋·푸시·PR 생성·병합·배포는 수행하지 않았다.

### 독립 검증자 재현 안내

1. 현재 두 TASK의 미커밋 변경 36개 파일 또는 이를 담은 후속 커밋·PR을 확보한다. TASK-007의 당시 작업 기록은 현재 없으므로 구현 코드·테스트와 이 보고서의 실행 이력을 함께 확인한다. 다른 구현 스냅샷을 검증했다면 SHA와 결과를 다시 기록한다.
2. lockfile 기준 의존성 및 Playwright Chromium을 준비하고 `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 실행한다.
3. §4의 TASK-007·008 E2E 명령을 실행한다. Windows에서 테스트용 서버 종료가 지연되면 별도 `vite preview --host 127.0.0.1 --port 4173 --strictPort`를 준비하고 기존 서버 재사용 설정으로 실행한 뒤, 검증자가 시작한 서버만 종료한다.
4. TC-06의 기본·메가·부재·폼 불일치, TC-07의 추가·해제·새로고침·빈 목록·손상/차단 복구, TC-08의 모바일·키보드·삭제 후 포커스, TC-09의 실패·재시도·캐시와 정책·경로 범위를 확인한다. D-007-01·D-008-01의 처리 여부도 기록한다.
5. 실제 검증자·환경·명령 결과·승인 근거를 기록하고 PASS/FAIL/BLOCKED를 새로 판정한다. 이 보고서의 자체 검증 결과만으로 독립 QA PASS를 선언하지 않는다.
