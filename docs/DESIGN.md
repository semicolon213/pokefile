# PokeFile 설계 명세서 (DESIGN)

- 버전: 0.3 / **디자인 시안 반영 제안, 팀 승인 전**
- 기준: 1주차 보고서, `SRS.md`, 포켓몬 도감 목록 PC 시안
- 확정 기술: React + Vite, React Router, TanStack Query, Recharts, PokéAPI, data.pkmn.cc, localStorage
- 미확정: 배포 플랫폼, 라우트 상세, 폼 처리 범위, 테스트 프레임워크
- 문서 성격: **화면 디자인 + 프론트엔드 설계**. 본 문서의 제안 사항은 `SRS.md`를 자동 변경하지 않는다.

## 1. 제품 목표와 디자인 방향

PokeFile은 별도 서버와 계정 없이 브라우저에서 포켓몬 정보를 탐색하는 정적 React 웹사이트다. 목록 탐색, 상세 정보 확인, 실전 데이터 조회, 즐겨찾기를 제공한다.

디자인 방향은 **현대적인 정보 탐색 웹사이트에 포켓몬 도감의 시각적 특징을 적용**하는 것이다.

- **웹사이트다운 사용성:** 고정된 정보 계층, 익숙한 검색·필터·정렬, 반응형 카드 목록, 명확한 이동 경로
- **도감다운 인상:** 빨간색 강조, 몬스터볼 형태의 아이콘, 도감 번호, 타입 배지, 세대 구분, 포켓몬 이미지
- **절제된 장식:** 게임 화면 전체를 복제하거나 픽셀 장식을 남용하지 않는다. 장식은 탐색을 방해하지 않아야 한다.
- **정보 우선:** 이미지가 없어도 번호·이름·타입을 읽을 수 있어야 한다.
- **한국어 우선:** 화면에 표시하는 메뉴, 버튼, 필터, 안내 문구, 포켓몬 이름과 타입은 한국어를 기본으로 한다. 코드의 식별자와 외부 API 필드명은 변경하지 않는다.
- **오류 격리:** 외부 API의 일부 실패가 전체 페이지 장애로 이어지지 않도록 화면 단위로 처리한다.

### 1.1 디자인 시안의 범위

PC 시안에는 상단 헤더, 좌측 세대 메뉴, 중앙 탐색 영역, 우측 정보 패널이 있다. **시안은 시각적 방향을 보여주는 참고 자료**이며, 실제 포켓몬 수·세대별 수치·추천 문구는 API와 요구사항을 기준으로 표시한다. 시안에 보이는 모든 기능이 구현 확정된 것은 아니다.

### 1.2 범위 구분

| 구분 | 내용 | 상태 |
|---|---|---|
| 필수 | 포켓몬 목록, 검색, 타입·세대 필터, 정렬, 카드 상세 이동 | 기존 범위 기반 |
| 필수 | 상세 기본 정보, 종족값 차트, 진화·출현·실전 데이터의 가능한 범위 표시 | 기존 범위 기반 |
| 필수 | 즐겨찾기 저장·해제 및 목록 | 기존 범위 기반 |
| 제안 | 도감 소개 배너와 요약 통계 | 디자인 요소, 데이터 확인 필요 |
| 제안 | 우측 '이번 주의 포켓몬' | 추천 선정 기준 및 데이터 소스 승인 필요 |
| 제안 | 우측 '최근 본 포켓몬' | 저장 정책 및 localStorage 계약 승인 필요 |
| 제안 | 타입 상성·포켓몬 비교 전용 페이지 | `SRS.md` 범위 확인 후 결정 |

## 2. 화면 구성 및 정보 구조

### 2.1 PC 도감 목록 화면 (`/` 제안)

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 포켓파일 로고   포켓몬 도감 | 타입 상성* | 포켓몬 비교* | 즐겨찾기  검색 │
├──────────────┬───────────────────────────────────────┬───────────────────────┤
│ 도감 사이드바│ 도감 소개 배너 / 요약 정보            │ 추천 포켓몬*          │
│              ├───────────────────────────────────────┤                       │
│ 전체         │ 검색 입력 / 검색 실행                 ├───────────────────────┤
│ 1세대        │ 타입 필터 / 추가 필터                  │ 최근 본 포켓몬*       │
│ 2세대        │ 결과 수 / 정렬 / 보기 전환*            │                       │
│ ...          │ 포켓몬 카드 그리드                    │                       │
│ 9세대        │ [카드] [카드] [카드] [카드] ...        │                       │
│              │ 추가 목록 불러오기                    │                       │
└──────────────┴───────────────────────────────────────┴───────────────────────┘
* 승인 전 제안 기능
```

**영역별 규칙**

1. **상단 헤더:** 화면 로고 표기는 `포켓파일`을 기본으로 한다(브랜드 표기 최종 승인 필요). 메뉴는 `포켓몬 도감`, `타입 상성`, `포켓몬 비교`, `즐겨찾기`로 표기하며, 미확정 메뉴는 노출하지 않는다. 빠른 검색(선택)과 현재 메뉴 강조를 제공한다.
2. **좌측 사이드바:** 전체 및 세대별 목록. 선택한 세대는 빨간 배경 또는 명확한 강조선으로 표시한다. 세대별 수치는 신뢰할 수 있는 데이터가 있을 때만 표시한다.
3. **중앙 소개 배너:** 도감 콘셉트를 보여주는 장식 영역. 이미지 로딩 실패 시 단색 배경과 텍스트만 남겨도 기능이 유지되어야 한다. 통계 수치는 실제 데이터 기준으로 표시한다.
4. **검색:** 이름(한국어·영어) 및 도감 번호를 대상으로 한다. 검색창 안내는 `포켓몬 이름 또는 도감 번호를 입력하세요`, 실행 버튼은 `검색`, 초기화 버튼은 `초기화`로 표기한다. 입력 중 검색인지 버튼 제출 방식인지는 구현 전에 결정한다. 헤더 검색과 본문 검색을 동시에 둘 경우 동일한 검색 상태를 공유한다.
5. **필터:** 타입, 세대. 화면에서는 `전체 타입`, `전체 세대`, `불꽃`, `물`, `풀` 등 한국어로 표기한다. 필터 적용 결과가 없으면 빈 결과 안내와 초기화 동작을 제공한다.
6. **정렬:** 기본값은 `도감 번호순`으로 표시한다. 이름순 등 추가 정렬 기준은 데이터 지원 여부를 확인한 뒤 확정한다.
7. **카드 목록:** 이미지, 도감 번호, 이름, 타입, 즐겨찾기 버튼을 표시한다. 카드 본문 선택 시 상세 화면으로 이동한다.
8. **우측 패널:** 추천·최근 본 기능을 승인할 때만 구현한다. 승인 전에는 해당 열을 제거하고 중앙 영역을 확장한다.

### 2.2 포켓몬 상세 화면 (`/pokemon/:id` 제안)

- 상단: 목록으로 돌아가기, 도감 번호, 한국어·영어 이름, 타입, 즐겨찾기
- 대표 영역: 공식/허용된 이미지, 기본 정보(키·몸무게 등 사용 가능한 항목)
- 정보 영역: 종족값(Recharts + 텍스트 수치), 진화 단계, 출현 정보, 실전 세팅
- 데이터가 없는 부가 영역은 '정보 없음'을 표시하고 다른 영역은 계속 보여준다.
- 폼별 데이터가 다를 경우 폼 선택 UI와 식별자 매핑 계약을 먼저 확정한다.

### 2.3 즐겨찾기 화면 (`/favorites` 제안)

- 도감 목록과 동일한 카드 컴포넌트를 재사용한다.
- 즐겨찾기가 없을 때 안내 문구와 도감으로 이동하는 링크를 제공한다.
- localStorage가 차단되거나 손상된 경우 화면 전체가 중단되지 않아야 한다.

### 2.4 선택 기능 화면

타입 상성, 포켓몬 비교는 시안의 상단 메뉴에 표시되지만 기존 설계에서는 선택 기능이다. `SRS.md`에서 확정되기 전에는 메뉴를 노출하지 않거나 비활성 안내로 처리한다. **작동하지 않는 메뉴를 완성된 기능처럼 표시하지 않는다.**

## 3. 디자인 토큰

디자인 값은 초기 제안이며 실제 브라우저 시안 검토 후 확정한다. 공통 CSS 변수 또는 테마 파일에서 관리하고 화면별 하드코딩을 피한다.

### 3.1 색상

| 토큰 | 제안 값 | 용도 |
|---|---|---|
| `--color-primary` | `#E84B4B` | 주요 버튼, 선택 메뉴, 강조 |
| `--color-primary-hover` | `#D83E3E` | 주요 버튼 hover |
| `--color-background` | `#F5F6F8` | 페이지 배경 |
| `--color-surface` | `#FFFFFF` | 카드, 입력창, 패널 |
| `--color-text` | `#242933` | 본문·제목 |
| `--color-muted` | `#667085` | 설명·보조 정보 |
| `--color-border` | `#E5E7EB` | 테두리·구분선 |
| `--color-focus` | `#2563EB` | 키보드 포커스 |

포켓몬 타입 배지는 **타입별 색상표를 한 곳에서 관리**한다. 색상만으로 타입을 구분하지 않고 타입 이름을 반드시 표시한다. 타입 색상 전체 목록은 API 타입 식별자와 함께 별도 토큰 파일에서 확정한다.

### 3.2 타이포그래피

- 기본: `Pretendard`, `Noto Sans KR`, 시스템 sans-serif 순서(폰트 제공·라이선스 확인)
- 본문: 14~16px, 줄간격 1.5 내외
- 페이지 제목: 28~32px, 섹션 제목: 18~22px
- 카드 이름: 15~16px, 도감 번호: 12~13px
- 작은 글씨라도 중요 정보는 충분한 대비를 확보한다.

### 3.3 간격과 형태

- 간격 기준: 4px 배수 (`4, 8, 12, 16, 24, 32`)
- 카드 둥근 모서리: 12~16px, 입력창·버튼: 10~12px
- 카드 그림자: 약하게 사용하고 hover 시에만 소폭 강조
- 주요 클릭 영역: 모바일 기준 최소 약 44×44px 권장
- 과도한 애니메이션과 배경 효과는 사용하지 않는다.

## 3.4 화면 언어 및 한국어 표기 규칙

- **기본 화면 언어는 한국어(`ko-KR`)**다. 메뉴, 버튼, 검색 안내, 필터, 정렬, 오류 문구, 빈 상태, 상세 정보 항목을 한국어로 작성한다.
- **포켓몬 이름:** PokéAPI species의 한국어 이름을 우선 사용한다. 한국어 이름이 없는 경우에만 영문 이름을 표시하고, 임의로 번역하지 않는다.
- **타입:** API 내부 값(`fire`, `water`, `grass` 등)은 유지하고 화면에는 `불꽃`, `물`, `풀`처럼 한국어 이름을 표시한다. 모든 타입에 대해 단일 매핑 표를 사용한다.
- **세대:** `1세대`, `2세대` 등으로 표시하고, 지방 이름이 필요하면 `관동지방` 등 한국어로 표시한다.
- **도감 번호:** `#0001`처럼 통일한다. 숫자는 원본 데이터를 사용하며 앞자리 0은 화면에서만 붙인다.
- **상세 정보:** `키`, `몸무게`, `특성`, `종족값`, `진화`, `출현 정보`, `실전 세팅`으로 표기한다. 수치 단위는 `m`, `kg` 등 국제 단위를 사용한다.
- **영어 표기 허용 범위:** 제품 내부 코드, 라이브러리, API·기술 이름(React, PokéAPI 등), 공식 고유명사와 한국어 데이터가 없는 포켓몬 이름. 사용자가 보는 화면에 영어 임시 문구(`Search`, `Loading`, `Favorites` 등)를 남기지 않는다.
- **브랜드:** 문서와 저장소 이름은 `PokeFile`로 유지하되, 화면에서는 `포켓파일`을 기본으로 한다. 공식 로고 영문 병기 여부는 팀에서 결정한다.

| 상황 | 화면에 표시할 한국어 문구 예시 |
|---|---|
| 검색창 | 포켓몬 이름 또는 도감 번호를 입력하세요 |
| 검색 결과 | 검색 결과 24마리 |
| 정렬 | 도감 번호순 / 이름순(지원 시) |
| 즐겨찾기 버튼 | 즐겨찾기 추가 / 즐겨찾기 해제 |
| 목록 로딩 | 포켓몬을 불러오는 중입니다. |
| 검색 결과 없음 | 검색 결과가 없습니다. 검색어나 필터를 확인해 주세요. |
| 목록 조회 오류 | 포켓몬 정보를 불러오지 못했습니다. |
| 재시도 버튼 | 다시 시도 |
| 상세 정보 없음 | 등록된 정보가 없습니다. |
| 즐겨찾기 비어 있음 | 즐겨찾기한 포켓몬이 없습니다. |
| 목록 추가 로딩 | 포켓몬 더 보기(버튼 사용 시) |

한국어 문구는 `shared`의 공통 메시지 파일에서 관리할 수 있다. 화면마다 서로 다른 번역을 작성하지 않는다.

## 4. 반응형 레이아웃

아래 수치는 **초기 제안**이며 실제 시안과 콘텐츠 길이를 기준으로 조정한다.

| 구간 | 화면 구성 | 카드 열 수 |
|---|---|---|
| 넓은 PC (`≥ 1440px`) | 좌측 세대 메뉴 + 중앙 목록 + 우측 보조 패널(승인 시) | 중앙 영역 기준 4~6열 |
| 일반 PC (`1024~1439px`) | 좌측 메뉴 + 중앙 목록, 우측 패널은 숨김/하단 이동 | 3~4열 |
| 태블릿 (`768~1023px`) | 세대 메뉴를 상단 필터 또는 드로어로 전환 | 3열 |
| 모바일 (`< 768px`) | 단일 콘텐츠 열, 필터 접기/펼치기 | 2열 |

- 고정된 전체 너비보다 **중앙 목록의 가용 너비**를 우선한다.
- 검색창과 필터가 좁아지면 줄바꿈 또는 접기 UI로 전환한다.
- 모바일에서 우측 보조 패널은 기본적으로 제거하거나 하단으로 옮긴다.
- 헤더 메뉴는 모바일에서 축약하며 키보드·스크린리더 접근성을 유지한다.
- 카드 그리드는 `minmax` 등으로 최소 카드 너비를 보장한다.

## 5. 공통 컴포넌트 명세

| 컴포넌트 | 필수 표시·동작 | 상태 |
|---|---|---|
| `AppHeader` | 로고, 주요 탐색, 현재 위치 표시 | 기본/모바일 |

### 5.1 카드 동작 규칙

- 카드 본문 클릭 또는 Enter 키: 상세 페이지 이동
- 즐겨찾기 버튼 클릭: 저장 상태만 변경하고 카드 이동은 발생하지 않음
- 이미지가 없으면 공통 대체 이미지 또는 아이콘 표시
- 타입은 색상 배지와 텍스트를 함께 표시
- 카드 높이는 가능한 한 일정하게 유지하되 긴 이름을 잘라 의미를 잃지 않도록 처리
- 목록의 각 카드에 안정적인 `PokemonId`를 key로 사용

### 5.2 인터랙션과 접근성

- 검색창에는 명확한 레이블과 입력 목적을 제공한다.
- 현재 선택 필터는 색상 외에도 선택 표시를 제공한다.
- 모든 버튼·링크·필터는 키보드로 조작 가능해야 한다.
- 포커스 표시를 제거하지 않는다.
- 로딩·오류·결과 없음 메시지는 텍스트로 제공한다.
- 차트는 그래프만 보여주지 않고 동일한 수치를 텍스트로 제공한다.
- 움직임 감소 설정을 존중한다.

## 7. 데이터 처리 흐름

1. PokéAPI에서 검색에 필요한 목록을 수집한다.
2. species의 한국어 이름을 연결해 클라이언트 검색 인덱스를 구성한다.
3. 검색어 → 타입·세대 필터 → 정렬 → 가시 항목 분할 순서로 표시한다. **처리 순서는 제안이며 실제 성능에 따라 조정 가능하다.**
4. 상세 진입 시 TanStack Query로 기본·종·진화·출현·실전 데이터를 가능한 범위에서 분리 조회한다.
5. 외부 응답은 `shared/models`의 정규화 모델로 변환한다.
6. 부가 데이터 요청이 실패해도 기본 상세 화면은 유지한다.
7. 필터·정렬 변경 시 목록의 표시 시작 위치를 적절히 초기화한다.

### 7.1 공통 모델 초안

```ts
type PokemonId = number;

type PokemonSummary = {
  id: PokemonId;
  nameEn: string;
  nameKo?: string;
  types: string[];
  generation?: string;
  imageUrl?: string;
};

type Loadable<T> =
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'empty' }
  | { status: 'error'; message: string };
```

이 모델은 팀 승인 전 제안이며 PokéAPI 응답을 그대로 복사한 것이 아니다. `generation`의 표현 형식, 폼 식별자, 타입 표준값을 먼저 합의한다.

## 9. 상태 관리와 캐싱

- **서버 상태:** TanStack Query. Query Key는 리소스, ID, 폼, 게임 등 실제 조회 차원을 포함한다.
- **UI 상태:** 검색어, 선택 필터, 정렬, 표시 개수는 화면 범위에서 관리한다. URL 쿼리 동기화는 팀 승인 후 결정한다.
- **즐겨찾기:** localStorage에 ID 중심으로 저장한다. 중복 저장과 JSON 파싱 오류를 방어한다. 키·버전·스키마는 팀 확정이 필요하다.
- **최근 본 항목(선택):** 기능 승인 시에만 localStorage 사용 여부와 최대 저장 개수·삭제 정책을 정의한다.
- **캐싱 정책:** staleTime, gcTime, 초기 로딩 전략, 동시 요청 제한은 실제 API 동작과 성능 측정 후 확정한다.
- **목록 추가 로딩:** 기존 SRS의 무한 스크롤 요구를 우선한다. 로딩 실패 시 재시도 수단을 제공한다.

## 10. 오류 및 빈 상태

| 상황 | 화면 동작 |
|---|---|
| 목록 최초 로딩 | 카드 영역 스켈레톤 또는 로딩 안내 |
| 검색 결과 없음 | 결과 없음 안내, 검색어·필터 초기화 |
| 목록 API 실패 | 오류 안내, 재시도 버튼 |
| 포켓몬 이미지 실패 | 대체 이미지·번호·이름 유지 |
| 상세 기본 데이터 실패 | 상세 오류 화면과 목록 이동·재시도 |
| 상세 부가 데이터 실패 | 해당 섹션만 오류 또는 데이터 없음 표시 |
| 한국어 이름 누락 | 영문 이름 표시(정책 승인 필요) |
| Smogon 폼 매핑 실패 | 임의의 실전 세팅을 만들어 표시하지 않음 |
| localStorage 접근 실패 | 안내 후 저장 기능 비활성, 탐색은 계속 가능 |

## 11. 디자인 자산 및 저작권

- 포켓몬 이미지, 로고, 게임 화면·배경을 사용할 경우 **출처, 사용 조건, 재배포 가능 여부**를 확인한다.
- 공식 게임 UI나 브랜드 로고를 그대로 복제하기보다 자체 제작한 도감형 UI를 사용한다.
- 시안의 배너 이미지와 장식은 최종 사용 허가가 확인된 자산으로 교체할 수 있어야 한다.
- 외부 이미지 주소를 사용할 경우 로딩 실패 대체 표시를 제공한다.
- 공개 배포 시 비공식 팬 프로젝트임을 명확히 표시할지 팀에서 검토한다. 이 문구만으로 사용 허가가 생기지는 않는다.

## 12. 구현 순서 및 검수 기준

### 12.1 권장 구현 순서

1. 공통 디자인 토큰, 전역 글꼴, 헤더·레이아웃 골격
2. 도감 목록 카드와 더미 데이터 기반 반응형 화면
3. 실제 API 연결, 검색·필터·정렬·무한 스크롤
4. 상세 화면과 섹션별 데이터 조회
5. 즐겨찾기 연동
6. 접근성, 로딩·오류 상태, 모바일 점검
7. 승인된 선택 기능과 우측 보조 패널 추가

### 12.2 화면 검수 체크리스트

- [ ] PC에서 헤더·사이드바·목록의 정보 계층이 시안과 일치한다.
- [ ] 모바일에서 가로 스크롤 없이 검색과 카드 목록을 사용할 수 있다.
- [ ] 카드의 번호·이름·타입이 이미지 실패 시에도 보인다.
- [ ] 검색, 필터, 정렬, 목록 추가 로딩이 함께 동작한다.
- [ ] 필터 결과 없음과 API 오류를 구분한다.
- [ ] 즐겨찾기 버튼을 눌러도 카드 상세로 이동하지 않는다.
- [ ] 키보드로 주요 탐색과 즐겨찾기를 조작할 수 있다.
- [ ] 상세 차트에 텍스트 수치가 함께 표시된다.
- [ ] 일부 부가 데이터 실패가 상세 전체를 중단시키지 않는다.
- [ ] SRS에 없는 기능을 임의로 추가하지 않았다.
- [ ] 메뉴·버튼·필터·상태 안내가 한국어로 표시된다.
- [ ] 한국어 포켓몬 이름과 타입이 올바르게 표시되며, 누락된 이름만 영문으로 대체된다.

## 14. 설계 변경 관리

공통 타입, API 계약, 라우팅, 패키지 의존성, 디자인 토큰, 공통 UI 변경은 이슈 또는 ADR에 변경 이유와 영향 범위를 기록한 뒤 영향 담당자와 합의한다. 실제 승인·PR 규칙은 `OWNERSHIP.md`, `WORKFLOW.md`를 따른다.

**문서 우선순위:** 기능 범위는 `SRS.md`, 담당·변경 권한은 `OWNERSHIP.md`와 `WORKFLOW.md`, 화면 표현과 공통 UI 기준은 본 `DESIGN.md`를 따른다. 충돌 시 임의 구현하지 않고 팀에서 결정한다.
