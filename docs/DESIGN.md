# PokeFile 설계 명세서 (DESIGN)

- 버전: 0.5 / 2026-11-04 — 시각 관련 절(§2 화면 구성, §3 디자인 토큰, §4 반응형, §5 컴포넌트)을 출시된 canon 리디자인 구현 기준으로 갱신. 팀 결정(ADR-004~014) 반영은 0.4와 같다.
- 기준: 1주차 보고서, `SRS.md`, 포켓몬 도감 목록 PC 시안, 출시 구현(`src/app/styles/global.css` 등)
- 확정 기술: React + Vite(TypeScript), React Router(HashRouter), TanStack Query, Recharts, PokéAPI, data.pkmn.cc, localStorage, Vitest·Testing Library·Playwright, GitHub Pages
- 확정 범위: #1~#1025(1~9세대) + 모든 폼 326개(상세 폼 전환, ADR-016), 라우트 `/`, `/pokemon/:id`, `/favorites`
- 문서 성격: **화면 디자인 + 프론트엔드 설계**. 본 문서의 제안 사항은 `SRS.md`를 자동 변경하지 않는다.
- 기계 판독용 토큰 사본: `.impeccable/design.json` (값의 기준은 `src/app/styles/global.css`)

## 1. 제품 목표와 디자인 방향

PokeFile은 별도 서버와 계정 없이 브라우저에서 포켓몬 정보를 탐색하는 정적 React 웹사이트다. 목록 탐색, 상세 정보 확인, 실전 데이터 조회, 즐겨찾기를 제공한다.

디자인 방향은 **현대적인 정보 탐색 웹사이트에 포켓몬 도감의 시각적 특징을 적용**하는 것이다. 2026-11-04 리디자인에서 **카테고리 표준**(익숙한 도감 사이트 관례: 상단 바·세대 사이드바·흰 카드 격자·절제된 빨간 강조)을 택해 구현했다(`PRODUCT.md` Brand Commitments).

- **웹사이트다운 사용성:** 고정된 정보 계층, 익숙한 검색·필터·정렬, 반응형 카드 목록, 명확한 이동 경로
- **도감다운 인상:** 빨간색 강조, 몬스터볼 형태의 자체 마크, 도감 번호, 타입 배지, 세대 구분, 포켓몬 이미지
- **절제된 장식:** 게임 화면 전체를 복제하거나 픽셀 장식을 남용하지 않는다. 장식은 탐색을 방해하지 않아야 한다. 소개 배너·히어로 없이 첫 화면부터 목록을 보여준다.
- **정보 우선:** 이미지가 없어도 번호·이름·타입을 읽을 수 있어야 한다.
- **한국어 우선:** 화면에 표시하는 메뉴, 버튼, 필터, 안내 문구, 포켓몬 이름과 타입은 한국어를 기본으로 한다. 코드의 식별자와 외부 API 필드명은 변경하지 않는다.
- **오류 격리:** 외부 API의 일부 실패가 전체 페이지 장애로 이어지지 않도록 화면 단위로 처리한다.

### 1.1 디자인 시안의 범위

PC 시안에는 상단 헤더, 좌측 세대 메뉴, 중앙 탐색 영역, 우측 정보 패널이 있다. **시안은 시각적 방향을 보여주는 참고 자료**이며, 실제 포켓몬 수·세대별 수치·추천 문구는 API와 요구사항을 기준으로 표시한다. 시안에 보이는 모든 기능이 구현 확정된 것은 아니다. 출시 구현에는 우측 정보 패널과 소개 배너가 없다(§2.1).

### 1.2 범위 구분

| 구분 | 내용 | 상태 |
|---|---|---|
| 필수 | 포켓몬 목록, 검색, 타입·세대 필터, 정렬, 카드 상세 이동 | 기존 범위 기반 |
| 필수 | 상세 기본 정보, 종족값 차트, 진화·출현·실전 데이터의 가능한 범위 표시 | 기존 범위 기반 |
| 필수 | 즐겨찾기 저장·해제 및 목록 | 기존 범위 기반 |
| 제안 | 도감 소개 배너와 요약 통계 | 출시 화면에 없음 — 첫 화면은 목록(§2.1). 세대별 수만 사이드바에 표시 |
| 제안 | 우측 '이번 주의 포켓몬' | 추천 선정 기준 및 데이터 소스 승인 필요 |
| 제안 | 우측 '최근 본 포켓몬' | 저장 정책 및 localStorage 계약 승인 필요 |
| 선택(확정) | 타입 상성·포켓몬 비교 등 선택 기능 FR-23~32 | ADR-015, 화면 설계는 구현 TASK에서 이 문서에 추가 |

## 2. 화면 구성 및 정보 구조

모든 화면은 공통 셸(`RootLayout`) 안에 있다: 높이 64px 상단 바(스크롤해도 위에 고정) + 본문(`max-width: 1440px`, 가운데 정렬, 안쪽 여백 24px, 모바일 16px).

### 2.1 PC 도감 목록 화면 (`/`)

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ (마크) PokeFile  [포켓몬 도감] 즐겨찾기   [(돋보기) 포켓몬 이름 또는 도감 번호] [검색] │  64px, sticky
├──────────────┬───────────────────────────────────────────────────────────────┤
│ 세대별 보기   │ (전체 타입) (노말) (불꽃) (물) … (페어리)        ← 타입 칩 한 줄 │
│ ▌전체   1025 │ 1025마리의 포켓몬                             [도감 번호순 ▾] │
│  1세대 관동…  │ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐                     │
│  2세대 성도…  │ │#001│ │#002│ │    │ │    │ │    │ │    │  auto-fill 격자     │
│  …           │ │ ◯  │ │ ◯  │ │    │ │    │ │    │ │    │  (최소 168px)       │
│  9세대 팔데아 │ │이름│ │이름│ …                                              │
│  248px,sticky│ └────┘ └────┘   (끝에 도달하면 자동 추가 로딩)                 │
└──────────────┴───────────────────────────────────────────────────────────────┘
```

**영역별 규칙 (출시 구현)**

1. **상단 바:** 왼쪽에 자체 마크(`BrandMark`, 위 빨강·아래 흰 원) + `PokeFile`(20px/800). 메뉴는 `포켓몬 도감`, `타입 상성`(TASK-021), `즐겨찾기` 세 탭. 현재 탭은 옅은 빨강 면(`--color-primary-soft`) + 진한 빨강 글자(`--color-primary-ink`)로 표시하며, 상세(`/pokemon/*`)에서도 `포켓몬 도감` 탭을 현재 위치로 표시한다. 오른쪽 끝에 헤더 검색(입력창 320px + 빨간 `검색` 버튼). 구현되지 않은 메뉴(`포켓몬 비교`)는 노출하지 않는다(§2.4). 검색창 왼쪽에 `내 게임` 선택(FR-26: 세대별로 묶은 게임 버전, 기본 `전체 게임`)을 둔다. 모바일(≤767px)은 헤더가 여러 줄이므로 고정하지 않는다.
2. **좌측 사이드바(248px):** 제목 `세대별 보기`, 항목 `전체`와 `1세대`~`9세대`(지방 이름 병기, 예: `1세대 관동지방`, 세대 목록은 scope.json)와 항목별 포켓몬 수(tabular 숫자). 지방을 고르면 그 **지방 도감 전체**를 보여 주며, 수는 지방 도감 수다(판은 내 게임을 따름, ADR-017). `전체`는 전국 도감 수. 선택 항목은 옅은 빨강 면 + 굵은 진한 빨강 글자 + `aria-pressed`. 항목 높이 최소 44px. 스크롤 시 상단 바 아래에 고정(sticky).
3. **소개 배너 없음:** 히어로·배너·요약 통계를 두지 않는다. 페이지 제목 `포켓몬 도감`은 화면에 보이지 않는 `h1`(`.visually-hidden`)로만 둔다.
4. **검색:** 상단 바의 헤더 검색 하나만 있다(본문 검색 없음). 이름(한국어·영어) 및 도감 번호 대상. 검색창 안내 `포켓몬 이름 또는 도감 번호`, 실행 버튼 `검색`, 입력값이 있을 때만 입력창 안에 `초기화` 버튼을 표시한다. **한 글자 입력할 때마다 바로 조회**한다(ADR-011, 2026-11-04 개정). 검색 버튼·Enter도 동작한다. 입력하면 URL 쿼리 `q`를 쓴다: 목록 화면에서는 현재 필터를 유지한 채 `q`만 바꾸고(replace, 기록을 쌓지 않음), 다른 화면에서는 도감 목록(`/`)으로 이동해 이어서 입력한다(입력창 포커스 유지). 내 게임(`game`)은 유지한다. 뒤로 가기 등으로 URL `q`가 바뀌면 입력창도 따라간다.
5. **타입 필터:** 본문 맨 위에 `전체 타입` + 18개 타입 칩을 한 줄(폭이 모자라면 줄바꿈)로 표시. 타입은 최대 2개까지 골라 그 조합을 모두 가진 포켓몬만 본다(2개를 고르면 나머지 칩은 비활성, 칩 아래 안내 문구). 같은 타입을 다시 누르면 해제, `전체 타입`은 모두 해제. 세대 필터는 사이드바가 담당한다. 결과가 없으면 점선 상자 안내 `검색 결과가 없습니다. 검색어나 필터를 확인해 주세요.` + `검색어·필터 초기화` 버튼.
6. **결과 수·정렬:** 타입 칩 아래 한 줄에 결과 수와 정렬 select. 결과 수는 필터가 없을 때 `<b>N</b>마리의 포켓몬`, 검색어·필터가 있을 때 `검색 결과 <b>N</b>마리`(숫자는 16px/800, tabular). 정렬은 `도감 번호순`(기본), `이름순` 2종이며 이름순은 화면 표시 이름(한국어 우선) 기준. 지방을 고르면 `지방 도감 순`(기본) / `전국 도감 번호순` / `이름순` 3종이 되고, 결과 수 아래에 판 안내(13px, 보조 글자색: `성도지방 도감 전체 · 하트골드·소울실버 기준`, 내 게임이 없으면 `(내 게임을 고르면 그 게임의 도감으로 바뀝니다)`)를 표시한다(ADR-017).
7. **카드 격자:** `repeat(auto-fill, minmax(168px, 1fr))`, 간격 16px. 카드는 도감 번호, 스프라이트(회색 원판 위), 이름, 타입 배지, 즐겨찾기 별을 표시한다. 카드 본문 선택 시 상세 화면으로 이동한다. 최초 로딩 시 카드 모양 스켈레톤 12장과 `포켓몬을 불러오는 중입니다.`를 표시한다.
8. **우측 패널 없음:** 추천·최근 본 기능은 승인 전이므로 해당 열이 없고 본문이 남은 폭을 모두 쓴다.

### 2.2 포켓몬 상세 화면 (`/pokemon/:id`)

```text
← 도감 목록으로
#0006  리자몽  Charizard                                    (별 버튼)
[기본][메가X][메가Y][거다이맥스]           ← 폼이 있는 종만
메가리자몽X                                ← 메가 폼 선택 시 폼 이름
┌ 기본 정보 (7fr) ───────────────────┐ ┌ 종족값 (5fr) ───────────┐
│ (216px 원판, 192 상자) │ 분류 타입 │ │ 가로 막대 차트 │ 수치 표 │
│                        │ 특성 키 몸무게 │ │                │ 합계    │
│ 도감 설명                            │ │                          │
└──────────────────────────────────────┘ └──────────────────────────┘
┌ 진화 (전체 폭) ──────────────────────────────────────────────────┐
┌ 출현 정보 (전체 폭) ─────────────────────────────────────────────┐
┌ 실전 추천 세팅 (전체 폭) ────────────────────────────────────────┐
```

- 상단: `도감 목록으로` 뒤로 가기 링크(화살표 아이콘) → 머리글(도감 번호 18px/700 muted, 한국어 이름 `h1` 32px/800, 한국어와 다를 때만 영어 이름 16px muted) + 오른쪽 즐겨찾기 별. 상세 영역 최대 폭 1200px.
- 폼 탭: 폼이 있는 종만 분할 버튼(segmented) 형태로 `기본`과 그 종의 모든 폼을 인덱스 순서로 표시한다(ADR-016). 단순 메가는 `메가`(리자몽·뮤츠는 `메가X`, `메가Y`), 그 밖은 폼 이름(`알로라의 모습`, `거다이맥스`, `워시로토무` 등). 탭이 많으면 줄을 바꾼다(피카츄 17개 — 선택 방식 개선은 TASK-024). 폼이 하나면 탭을 숨긴다. 선택한 폼은 URL `?form=`에 반영하고, 이미지·타입·특성·종족값·실전 세팅을 그 폼 기준으로 바꾼다. 기본이 아닌 폼 선택 시 탭 아래에 폼 전체 이름(18px/700, 예: `메가리자몽X`, `라이츄 (알로라의 모습)`, `거다이맥스 리자몽`)을 표시한다. 진화·출현 장소·도감 설명은 종 단위이므로 바꾸지 않는다.
- 섹션 배치: 1100px 이상에서 `기본 정보 | 종족값`을 7:5 두 열로 나란히, 그 아래 `타입 상성`, `진화`, `출현 정보`, `실전 추천 세팅`은 전체 폭. 1100px 미만은 한 열.
- 타입 상성(TASK-021, type-chart 공개 컴포넌트 `TypeMatchups`): 선택한 폼의 타입 기준 받는 피해를 `약점 ×4` / `약점 ×2` / `반감 ×½` / `반감 ×¼` / `무효 ×0` 줄로 묶어 타입 배지로 표시(1배·빈 줄 생략). 오른쪽 위 `전체 상성표` 링크(`/types?type=…`). 아래 안내 `나머지 타입은 보통(×1)입니다. 특성·테라스탈은 반영하지 않습니다.`
- 기본 정보: 216px 회색 원판 위 대표 이미지(showdown 애니메이션 GIF, ADR-013), 분류·타입·특성(숨겨진 특성 표시)·키·몸무게 정의 목록, 아래 구분선 뒤 `도감 설명`(최대 65ch).
- 종족값: Recharts 가로 막대(최대 255 기준 고정) + 같은 수치의 텍스트 표와 `합계`.
- 진화: 단계별 작은 카드(112px 폭, 96px 이미지 칸)를 잇고, 진화 조건(`Lv.16` 등)을 카드 사이에 표시. 현재 포켓몬 카드는 빨간 테두리 + 옅은 빨강 면. 분기 진화만 세로로 들여쓴다.
- 데이터가 없는 부가 영역은 '정보 없음'을 표시하고 다른 영역은 계속 보여준다.
- 기본 폼과 모든 폼(메가·거다이맥스·리전폼·기타)을 표시한다(ADR-016). 폼이 많은 종(피카츄 등)의 폼 선택 방식은 TASK-024에서 정한다.

### 2.3 즐겨찾기 화면 (`/favorites`)

- 화면 제목 `즐겨찾기`(28px/800)와 개수 안내, 도감 목록과 동일한 `PokemonCard`와 같은 격자 규칙(`minmax(168px, 1fr)`)을 재사용한다.
- 즐겨찾기가 없을 때 점선 상자 안내와 `도감으로 이동` 주 버튼을 제공한다.
- localStorage가 차단되거나 손상된 경우 화면 전체가 중단되지 않아야 한다. 안내는 옅은 노랑 경고 면(`--color-warning-soft` / `--color-warning-ink`)으로 표시한다.

### 2.4 선택 기능 화면

선택 기능은 ADR-015로 확정되었다(FR-23~32). 각 기능은 구현·병합되기 전까지 메뉴나 진입점을 노출하지 않는다. **작동하지 않는 메뉴를 완성된 기능처럼 표시하지 않는다.** `포켓몬 비교`(TASK-022)는 구현 전이라 메뉴가 없다.

#### 2.4.1 타입 상성 화면 (`/types`, TASK-021, FR-24)

- 제목 `타입 상성`(28px/800). 그 아래 두 영역(흰 면 + 1px 테두리 섹션).
- **받는 피해 계산:** 18개 타입 칩(목록 타입 필터와 같은 모양, 선택 시 타입 색 + 2px 진한 테두리)에서 방어 타입을 1~2개 고른다(2개면 나머지 비활성, `선택 해제` 점선 버튼). URL `?type=fire&type=flying`(표준 순서). 고르면 구분선 아래 `불꽃·비행 타입이 받는 피해` + 상세와 같은 배율 묶음.
- **전체 상성표:** 행 = 공격 타입, 열 = 방어 타입인 18×18 표. 칸은 참고 시안(`docs/image/type.jpeg`)처럼 공격 쪽 기준 색 — `2` 초록(`--eff-super-*`), `½` 빨강(`--eff-weak-*`), `0` 진회색(`--eff-none-*`), 보통은 빈 회색 칸. 숫자를 항상 적어 색만으로 구분하지 않는다. 범례를 표 위에 둔다. 고른 방어 타입 열은 머리 칸 2px 잉크 테두리 + 보통 칸 회색 면으로 강조한다. 좁은 화면은 표만 가로 스크롤(공격 타입 열 고정)하고 페이지는 넘치지 않는다.
- 받는 피해 묶음은 방어 쪽 관점이라 표의 초록·빨강을 쓰지 않고 `약점`/`반감`/`무효` 글자와 배율로 구분한다(같은 색이 두 화면에서 반대 뜻이 되지 않도록).
- 데이터: `src/features/type-chart/data/type-chart.json`(`npm run build:type-chart`가 PokéAPI `/type` `damage_relations`에서 생성, 6세대 이후 상성). `verify-api`가 현재 PokéAPI 값과 같은지 확인한다.

- **픽셀 아트 스프라이트:** `fitPixelArt(img, box)`로 상자 안에서 원본의 **정수배(1·2·3배…)로만** 키우고 `image-rendering: pixelated`로 그린다. 원본이 상자보다 크면 줄이지 않고 다음 이미지로 넘어간다(소수배 축소 금지).

  - 진화 카드: 96px 이미지 칸, 상자 96px(showdown 스프라이트는 대부분 1배).

## 3.4 화면 언어 및 한국어 표기 규칙

- **기본 화면 언어는 한국어(`ko-KR`)**다. 메뉴, 버튼, 검색 안내, 필터, 정렬, 오류 문구, 빈 상태, 상세 정보 항목을 한국어로 작성한다.
- **포켓몬 이름:** PokéAPI species의 한국어 이름을 우선 사용한다. 한국어 이름이 없는 경우에만 영문 이름을 표시하고, 임의로 번역하지 않는다.
- **타입:** API 내부 값(`fire`, `water`, `grass` 등)은 유지하고 화면에는 `불꽃`, `물`, `풀`처럼 한국어 이름을 표시한다. 모든 타입에 대해 단일 매핑 표(`TYPE_LABELS`)를 사용한다.
- **세대:** `1세대`, `2세대` 등으로 표시하고, 지방 이름이 필요하면 `관동지방` 등 한국어로 표시한다(`GENERATION_LABELS`).
- **도감 번호:** `#0001`처럼 통일한다. 숫자는 원본 데이터를 사용하며 앞자리 0은 화면에서만 붙인다.
- **상세 정보:** `키`, `몸무게`, `특성`, `종족값`, `진화`, `출현 정보`, `실전 세팅`으로 표기한다. 수치 단위는 `m`, `kg` 등 국제 단위를 사용한다.
- **영어 표기 허용 범위:** 제품 내부 코드, 라이브러리, API·기술 이름(React, PokéAPI 등), 공식 고유명사와 한국어 데이터가 없는 포켓몬 이름, 브랜드 `PokeFile`. 사용자가 보는 화면에 영어 임시 문구(`Search`, `Loading`, `Favorites` 등)를 남기지 않는다.
- **브랜드:** 화면·문서·저장소 모두 `PokeFile`(영문)로 표기한다(`PRODUCT.md` Brand Commitments). 상단 바 마크는 공식 로고가 아닌 자체 도형이다.
- **문서 제목:** 화면마다 `useDocumentTitle`로 `<화면 이름> - PokeFile`을 쓴다(`포켓몬 도감 - PokeFile`, `즐겨찾기 - PokeFile`, `<포켓몬 이름> - PokeFile`).

| 상황 | 화면에 표시할 한국어 문구 예시 |
|---|---|
| 검색창 | 포켓몬 이름 또는 도감 번호를 입력하세요 |
| 검색 결과 | 검색 결과 24마리 |
| 정렬 | 도감 번호순 / 이름순(지원 시) |
| 즐겨찾기 버튼 | 즐겨찾기 추가 / 즐겨찾기 해제 |
| 목록 로딩 | 포켓몬을 불러오는 중입니다. |
| 검색 결과 없음 | 검색 결과가 없습니다. 검색어나 필터를 확인해 주세요. |
| 목록 조회 오류 | 포켓몬 정보를 불러오지 못했습니다. |
| 재시도 버튼 | 다시 시도 |
| 상세 정보 없음 | 등록된 정보가 없습니다. |
| 즐겨찾기 비어 있음 | 즐겨찾기한 포켓몬이 없습니다. |
| 목록 추가 로딩 | 포켓몬을 더 불러오는 중입니다. |
| 추가 로딩 실패 | 목록을 더 불러오지 못했습니다. + `다시 시도` |

한국어 문구는 `shared`의 공통 메시지 파일에서 관리할 수 있다. 화면마다 서로 다른 번역을 작성하지 않는다.

### 5.1 카드 동작 규칙

- 카드 본문 클릭 또는 Enter 키: 상세 페이지 이동
- 즐겨찾기 버튼 클릭: 저장 상태만 변경하고 카드 이동은 발생하지 않음
- 이미지가 없으면 공통 대체 이미지 또는 아이콘 표시(출시 구현: 원판 안의 빈 원)
- 타입은 색상 배지와 텍스트를 함께 표시
- 카드 높이는 가능한 한 일정하게 유지하되 긴 이름을 잘라 의미를 잃지 않도록 처리(이름은 `word-break: keep-all`로 줄바꿈, 자르지 않음)
- 목록의 각 카드에 안정적인 `PokemonId`를 key로 사용
- 카드 이미지는 `alt=""`(장식)로 둔다. 링크 텍스트에 이름이 이미 있으므로 이름이 두 번 읽히지 않게 한다. 상세 대표 이미지와 진화 이미지는 포켓몬 이름을 대체 텍스트로 쓴다.

### 5.2 인터랙션과 접근성

- 검색창에는 명확한 레이블과 입력 목적을 제공한다(숨김 레이블 `포켓몬 검색`, `role="search"`).
- 현재 선택 필터는 색상 외에도 선택 표시를 제공한다(`aria-pressed`, 굵기·채움 변화).
- 모든 버튼·링크·필터는 키보드로 조작 가능해야 한다.
- 포커스 표시를 제거하지 않는다(`:focus-visible` 2px `--color-focus` 윤곽선).
- 로딩·오류·결과 없음 메시지는 텍스트로 제공한다(결과 수·로딩은 `aria-live="polite"`).
- 차트는 그래프만 보여주지 않고 동일한 수치를 텍스트로 제공한다.
- 움직임 감소 설정을 존중한다(§3.3: 전환 끔, 정적 PNG 우선).
- 화면마다 고유한 문서 제목을 둔다(`useDocumentTitle`, WCAG 2.4.2).

## 7. 데이터 처리 흐름

1. PokéAPI에서 검색에 필요한 목록을 수집한다.
2. species의 한국어 이름을 연결해 클라이언트 검색 인덱스를 구성한다.
3. 검색어 → 타입·세대 필터 → 정렬 → 가시 항목 분할 순서로 표시한다. **처리 순서는 제안이며 실제 성능에 따라 조정 가능하다.**
4. 상세 진입 시 TanStack Query로 기본·종·진화·출현·실전 데이터를 가능한 범위에서 분리 조회한다.
5. 외부 응답은 `shared/models`의 정규화 모델로 변환한다.
6. 부가 데이터 요청이 실패해도 기본 상세 화면은 유지한다.
7. 필터·정렬 변경 시 목록의 표시 시작 위치를 적절히 초기화한다.

### 7.1 공통 모델 초안

```ts
type PokemonId = number;

type PokemonSummary = {
  id: PokemonId;
  nameEn: string;
  nameKo?: string;
  types: string[];
  generation?: string;
  imageUrl?: string;
};

type Loadable<T> =
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'empty' }
  | { status: 'error'; message: string };
```

이 모델은 **확정**되었다(ADR-009). PokéAPI 응답을 그대로 복사한 것이 아니다. `PokemonId`는 전국도감 번호(1~1025)이고, 폼은 `FormKey`로 구분한다. TASK-023에서 6세대 메가용(`'default' | 'mega' | 'mega-x' | 'mega-y'`)을 PokéAPI pokemon 이름에서 종 이름을 뺀 문자열(`gmax`, `alola`, `wash` 등)로 일반화했다(ADR-016). 폼 정보는 `PokemonSummary.forms`(`PokemonForm`: key·nameKo·nameEn·category·types·battleOnly)에 있다. `generation`은 PokéAPI 값(`generation-i`~`generation-ix`)을 그대로 쓰고, 타입은 PokéAPI 현재 타입 식별자(`fire`, `fairy` 등)를 쓴다(6세대 이후 타입 변경 없음).

## 9. 상태 관리와 캐싱

- **서버 상태:** TanStack Query. Query Key는 리소스, ID, 폼, 게임 등 실제 조회 차원을 포함한다.
- **UI 상태:** 검색어(`q`), 타입(`type`), 세대(`gen`), 정렬(`sort`)은 **URL 쿼리와 동기화**한다(ADR-011). 예: `/#/?q=피카츄&type=electric&gen=1&sort=name`. 표시 개수는 화면 범위에서 관리한다.
- **즐겨찾기:** 키 `pokefile:favorites`, 값 `{"version":1,"ids":[...]}` (ADR-012). 중복 저장과 JSON 파싱 오류를 방어한다.
- **최근 본 항목(선택):** 기능 승인 시에만 localStorage 사용 여부와 최대 저장 개수·삭제 정책을 정의한다.
- **캐싱 정책:** staleTime, gcTime, 초기 로딩 전략, 동시 요청 제한은 실제 API 동작과 성능 측정 후 확정한다.
- **목록 추가 로딩:** 무한 스크롤(버튼 없음). 목록 끝 감지 시 자동으로 추가한다. 로딩 실패 시 재시도 수단을 제공한다.

## 11. 디자인 자산 및 저작권

- 포켓몬 이미지, 로고, 게임 화면·배경을 사용할 경우 **출처, 사용 조건, 재배포 가능 여부**를 확인한다.
- 공식 게임 UI나 브랜드 로고를 그대로 복제하기보다 자체 제작한 도감형 UI를 사용한다.
- 시안의 배너 이미지와 장식은 최종 사용 허가가 확인된 자산으로 교체할 수 있어야 한다.
- 외부 이미지 주소를 사용할 경우 로딩 실패 대체 표시를 제공한다.
- 공개 배포 시 비공식 팬 프로젝트임을 명확히 표시할지 팀에서 검토한다. 이 문구만으로 사용 허가가 생기지는 않는다.

## 12. 구현 순서 및 검수 기준

### 12.1 권장 구현 순서

1. 공통 디자인 토큰, 전역 글꼴, 헤더·레이아웃 골격
2. 도감 목록 카드와 더미 데이터 기반 반응형 화면
3. 실제 API 연결, 검색·필터·정렬·무한 스크롤
4. 상세 화면과 섹션별 데이터 조회
5. 즐겨찾기 연동
6. 접근성, 로딩·오류 상태, 모바일 점검
7. 승인된 선택 기능과 우측 보조 패널 추가

### 12.2 화면 검수 체크리스트

- [ ] PC에서 헤더·사이드바·목록의 정보 계층이 시안과 일치한다.
- [ ] 모바일에서 가로 스크롤 없이 검색과 카드 목록을 사용할 수 있다.
- [ ] 카드의 번호·이름·타입이 이미지 실패 시에도 보인다.
- [ ] 검색, 필터, 정렬, 목록 추가 로딩이 함께 동작한다.
- [ ] 필터 결과 없음과 API 오류를 구분한다.
- [ ] 즐겨찾기 버튼을 눌러도 카드 상세로 이동하지 않는다.
- [ ] 키보드로 주요 탐색과 즐겨찾기를 조작할 수 있다.
- [ ] 상세 차트에 텍스트 수치가 함께 표시된다.
- [ ] 일부 부가 데이터 실패가 상세 전체를 중단시키지 않는다.
- [ ] SRS에 없는 기능을 임의로 추가하지 않았다.
- [ ] 메뉴·버튼·필터·상태 안내가 한국어로 표시된다.
- [ ] 한국어 포켓몬 이름과 타입이 올바르게 표시되며, 누락된 이름만 영문으로 대체된다.

## 14. 설계 변경 관리

공통 타입, API 계약, 라우팅, 패키지 의존성, 디자인 토큰, 공통 UI 변경은 이슈 또는 ADR에 변경 이유와 영향 범위를 기록한 뒤 영향 담당자와 합의한다. 실제 승인·PR 규칙은 `OWNERSHIP.md`, `WORKFLOW.md`를 따른다.

**문서 우선순위:** 기능 범위는 `SRS.md`, 담당·변경 권한은 `OWNERSHIP.md`와 `WORKFLOW.md`, 화면 표현과 공통 UI 기준은 본 `DESIGN.md`를 따른다. 충돌 시 임의 구현하지 않고 팀에서 결정한다.
