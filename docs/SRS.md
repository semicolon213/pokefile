# PokeFile 소프트웨어 요구사항 명세서 (SRS)

| 항목 | 내용 |
|---|---|
| 프로젝트명 | PokeFile — PokéAPI 기반 포켓몬 도감 검색 웹사이트 |
| 문서 버전 | 1.0 (초안) |
| 작성 기준 | 고급웹프로그래밍 PBL 1주차 주간진행보고서 (2026-10-27 제출 예정) |
| 팀명 | 오박사의 비밀 |
| 팀원 | 김형균, 임지섭, 성윤우 |
| 문서 상태 | 요구사항 정의 초안 — 구현 전 검토 필요 |

> **표기 원칙:** `확정`은 1주차 보고서에 명시된 사항, `제안`은 개발·테스트를 위해 구체화한 사항, `확인 필요`는 추가 조사나 팀 의사결정이 필요한 사항이다.

## 1. 개요

### 1.1 목적
본 문서는 PokeFile의 개발 범위, 기능 및 비기능 요구사항, 외부 데이터 연동 방식과 검증 기준을 정의한다. 팀원 간 구현 기준을 통일하고 이후 화면 설계, 개발, 테스트에 활용한다.

### 1.2 제품 개요
PokeFile은 별도 애플리케이션 서버 없이 웹 브라우저에서 동작하는 React 기반 포켓몬 도감이다. 사용자는 포켓몬을 검색하고, 조건에 따라 목록을 탐색하며, 상세 정보·종족값·진화·출현 장소·실전 추천 세팅을 확인할 수 있다. 즐겨찾기는 브라우저의 localStorage에 저장한다.

### 1.3 범위
**포함(확정):** 한국어·영어 이름 및 도감 번호 검색, 타입·세대 필터와 정렬, 카드 목록 및 무한 스크롤, 상세 정보, 종족값 차트, 진화 트리, 세대·게임별 출현 장소, Smogon 기준 실전 추천 세팅, 즐겨찾기, 반응형 UI, 로딩·오류 상태, 캐싱.

**선택(확정):** 이로치 이미지 및 울음소리, 타입 상성, 두 포켓몬 능력치 비교.

**범위 밖(제안):** 사용자 계정·로그인, 서버 데이터베이스, 자체 백엔드, AI 추천, Steam 연동, 즐겨찾기 기기 간 동기화. 이는 현재 서버리스 설계에 포함되지 않는다.

### 1.4 용어
| 용어 | 정의 |
|---|---|
| PokéAPI | 포켓몬의 기본 정보·종 정보·진화·출현 장소 등을 제공하는 공개 API |
| data.pkmn.cc | Smogon 기반 실전 세팅 데이터를 조회하기 위해 조사한 외부 데이터 출처 |
| 종족값 | HP, 공격, 방어, 특수공격, 특수방어, 스피드 등 기본 능력치 |
| 폼(Form) | 같은 포켓몬의 형태·변형 구분 |
| localStorage | 브라우저에 키-값 형태로 데이터를 저장하는 기능 |
| CORS | 서로 다른 출처의 브라우저 요청에 적용되는 접근 제어 정책 |

## 2. 전체 설명

### 2.1 사용자
| 사용자 | 주요 행동 |
|---|---|
| 일반 방문자 | 검색, 필터링, 상세 정보 조회, 진화·출현 장소·실전 세팅 확인 |
| 즐겨찾기 사용자 | 원하는 포켓몬을 저장하고 같은 브라우저에서 다시 조회 |

별도의 계정이나 권한 구분은 없다. (제안)

### 2.2 실행 환경 및 기술 스택
| 구분 | 기술/방식 | 상태 |
|---|---|---|
| 프론트엔드 | React + Vite | 확정 |
| 라우팅 | React Router | 확정 |
| 데이터 요청 및 캐시 | TanStack Query | 확정 |
| 차트 | Recharts | 확정 |
| 기본 포켓몬 데이터 | PokéAPI | 확정 |
| 실전 세팅 데이터 | data.pkmn.cc (Smogon 기반) | 확정 — 세부 매핑 검토 필요 |
| 로컬 저장 | localStorage | 확정 |
| 배포 | GitHub Pages, Vercel, Netlify 중 선택 | 후보 확정, 최종 플랫폼 미정 |

### 2.3 주요 제약 및 의존성
- 자체 백엔드 서버 없이 정적 빌드 결과물을 배포한다. (확정)
- 외부 API는 브라우저에서 직접 요청하며 CORS 허용 여부에 의존한다. 1주차에는 두 출처의 브라우저 호출 가능성을 테스트했다. (확정)
- 공개 API의 가용성·응답 속도·데이터 완전성을 애플리케이션이 보장할 수 없다. (제안)
- PokéAPI는 부분 문자열 검색을 직접 제공하지 않으므로 검색용 목록을 받아 클라이언트에서 필터링한다. (확정)
- 한국어 이름은 `/pokemon-species` 계열 데이터에서 별도로 구성해야 한다. (확정)
- 실전 세팅은 두 데이터 출처 간 이름·폼 표기 차이를 처리해야 한다. (확정)
- 일부 최신 세대 게임의 출현 장소 데이터가 비어 있을 수 있다. (확정)

## 3. 기능 요구사항

우선순위: **P0 필수**, **P1 선택**. 아래 검증 기준의 구체적 UI 동작은 보고서의 요구사항을 테스트 가능하게 풀어 쓴 **제안**이다.

|---|---|---|---|---|
| FR-01 | 사용자는 한국어 이름으로 포켓몬을 검색할 수 있어야 한다. | P0 | 확정 | 한국어 이름을 입력하면 대응하는 포켓몬이 결과에 나타난다. |
| FR-02 | 사용자는 영어 이름으로 포켓몬을 검색할 수 있어야 한다. | P0 | 확정 | 영어 이름 입력 시 대응하는 포켓몬이 결과에 나타난다. |
| FR-03 | 사용자는 도감 번호로 포켓몬을 검색할 수 있어야 한다. | P0 | 확정 | 유효한 도감 번호 입력 시 해당 포켓몬이 표시된다. |
| FR-04 | 사용자는 타입별로 목록을 필터링할 수 있어야 한다. | P0 | 확정 | 타입 선택 시 조건에 맞는 포켓몬만 표시된다. |

## 4. 비기능 요구사항

| ID | 요구사항 | 상태 | 검증 기준 |

| NFR-07 | 외부 데이터가 일부 누락되어도 나머지 상세 정보는 조회 가능하도록 처리한다. | 제안 | 특정 부가 정보 요청이 실패해도 전체 화면이 무조건 실패하지 않는다. |
| NFR-08 | 키보드 조작과 이미지 대체 텍스트 등 기본 접근성을 고려한다. | 제안 | 검색창·버튼을 키보드로 사용할 수 있고 주요 이미지에 설명이 있다. |

> **성능 목표(확인 필요):** 최초 목록 로딩 시간, 검색 반응 시간, 캐시 유지 시간, 지원 브라우저 버전은 1주차 보고서에서 수치로 정하지 않았다. 임의의 성능 수치를 확정 요구사항으로 사용하지 않는다.

## 5. 외부 인터페이스 및 데이터 요구사항

### 5.1 API 연동

| 출처 / 엔드포인트 | 목적 | 관련 요구사항 |
|---|---|---|
| PokéAPI `/pokemon` | 기본 정보, 타입, 특성, 종족값 및 목록 조회 | FR-02~08, FR-11~14 |
| PokéAPI `/pokemon-species` | 한국어 이름, 분류·설명, 세대 정보 | FR-01, FR-05, FR-12~13 |
| PokéAPI `/evolution-chain` | 진화 관계 조회 | FR-15 |
| PokéAPI `/pokemon/{id}/encounters` | 게임별 출현 장소 조회 | FR-16 |
| data.pkmn.cc | Smogon 기반 실전 추천 세팅 조회 | FR-17 |

위 경로는 보고서에 제시된 주요 API 계열을 정리한 것이다. 실제 요청 URL, 응답 필드, 페이징, 데이터 매핑 규칙은 구현 전 별도 검증한다.

### 5.2 데이터 처리 규칙

**DR-01 (확정)** 부분 문자열 검색을 위해 포켓몬 전체 목록을 최초 1회 받아 브라우저에서 필터링한다.

**DR-02 (확정)** 한국어 이름은 별도의 species 데이터를 사용해 검색 인덱스를 구성한다.

**DR-03 (확정)** 상세 정보에 필요한 여러 요청은 TanStack Query로 관리하여 중복 호출을 줄인다.

**DR-04 (확정)** PokéAPI와 data.pkmn.cc 사이의 포켓몬 이름·폼 표기 차이를 매핑한다.

**DR-05 (확정)** 최신 게임의 출현 장소 데이터가 비어 있으면 안내 문구를 표시한다.

**DR-06 (제안)** API 응답값이 누락되거나 매핑되지 않으면 `정보 없음`을 표시하고 다른 정보를 유지한다.

**DR-07 (제안)** 즐겨찾기는 고유한 포켓몬 식별자 배열로 저장하고 중복을 허용하지 않는다. 구체적인 저장 키·스키마는 구현 단계에서 확정한다.

### 5.3 데이터 흐름

```text

  └─ React UI / React Router
       ├─ 검색·필터·정렬 ── 클라이언트 검색 인덱스

       │                    ├─ PokéAPI

```

## 7. 대표 사용자 시나리오

### UC-01 포켓몬 검색 및 상세 조회
1. 사용자가 메인 페이지에서 한국어·영어 이름 또는 도감 번호를 입력한다.
2. 시스템이 검색 인덱스에서 일치하는 결과를 찾는다.
3. 사용자가 타입·세대 필터 또는 정렬을 적용한다.
4. 시스템이 결과 카드를 표시하고 스크롤에 따라 다음 항목을 추가한다.
5. 사용자가 카드를 선택하면 상세 페이지로 이동한다.
6. 시스템이 API 데이터를 조회하고 종족값·진화·출현 장소·실전 세팅을 표시한다.
7. 일부 데이터가 없으면 해당 영역에 안내 문구를 표시한다.

### UC-02 즐겨찾기 저장 및 조회
1. 사용자가 포켓몬 상세 화면에서 즐겨찾기를 추가한다.
2. 시스템이 localStorage에 식별자를 저장한다.
3. 사용자가 즐겨찾기 페이지로 이동하면 저장된 목록이 표시된다.
4. 사용자가 즐겨찾기를 해제하면 저장 목록이 갱신된다.
5. 새로고침 후에도 동일 브라우저의 저장 내용이 유지된다.
