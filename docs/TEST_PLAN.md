# 테스트 및 인수 계획

## 1. 원칙
기능 테스트, API 계약 테스트, 반응형 수동 확인, 정적 배포 확인을 분리한다.
AI 자체 보고와 실제 실행 결과를 구분한다. `SRS.md`의 FR/NFR/DR ID를 사용한다.

## 2. 테스트 계층 (도구 확정: ADR-007)
| 계층 | 대상 | 도구 | 명령 |
|---|---|---|---|
| Unit | 검색 정규화, 필터, 정렬, 즐겨찾기 직렬화, 이름 매핑 | Vitest | `npm test` |
| Integration | API adapter + UI의 로딩/오류/데이터 없음 | Vitest + React Testing Library(jsdom) | `npm test` |
| E2E | 검색 → 상세 → 즐겨찾기 → 새로고침, URL 쿼리 복원 | Playwright | `npm run test:e2e` |
| API contract | 실제 응답과 adapter 기대 필드 비교 | `node:test` (`scripts/verify-api/`) | `npm run verify:api` |
| Manual | 모바일/데스크톱, 키보드 조작, 차트 수치, 배포 URL(`/#/...`) 새로고침 | — | — |

- CI(모든 PR, `main`·`develop` push): `verify` 작업(lint · typecheck · test · build)과 `e2e` 작업(Playwright Chromium)을 함께 실행하며 둘 다 통과해야 한다. 다른 영역 화면 변경이 기존 E2E를 깨는 회귀(PR #2·#4)를 막기 위해 2026-11-04 추가했다.
- API contract(`npm run verify:api`)는 외부 API 상태에 좌우되므로 CI에 넣지 않고 필요할 때 수동 실행한다.
- 단위·통합 테스트는 외부 API를 직접 호출하지 않고 응답 샘플(fixture)을 사용한다.

## 4. QA PASS 기준
- 할당 TASK의 acceptance 항목이 모두 충족됨
- 해당 자동 테스트/빌드 명령 성공 및 로그 첨부
- 소유권 위반·의도하지 않은 공통 계약 변경 없음
- 심각한 결함 없음
- 미검증/데이터 한계는 명시하고 사람에게 판단 요청
테스트 환경이 없거나 실제 실행을 못 했다면 QA PASS가 아닌 BLOCKED.

## 5. 결함 심각도
- Blocker: 앱 실행 불가, 필수 기능 전면 장애
- Major: 핵심 요구사항 실패, 잘못된 포켓몬/세팅 연결
- Minor: 우회 가능한 UI 결함
- Trivial: 문구·간격 등 경미한 문제
